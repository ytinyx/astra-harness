这份文档回答“为什么这样实现”，不重复接口手册或测试日志。下表均对应当前 0.4 已有代码；阶段先后见 [版本索引](VERSION_TIMELINE.md)，运行语义见 [架构](ARCHITECTURE.md)，实际验证见 [交接记录](../HANDOFF.md)。

## 当前选择

| 选择 | 解决的问题 | 代价与适用范围 |
| --- | --- | --- |
| 自研 Engine，业务能力显式注入 | 让执行循环、权限和恢复路径可以直接阅读与实验 | 需要自己维护边界；不追求完整平台兼容 |
| 单 Worker、顺序工具批次、SQLite | 以较小状态空间验证执行、审批与恢复 | 单主机单用户；不能靠增加 Web worker 扩容 |
| 调用前保存 inflight，未知效果保守停止 | 防止重启后盲目重复写入 | 不确定窗口会牺牲任务完成率，需要人工核查 |
| 暂停发生在调用边界 | 保留原阶段、审批和预算，避免打断写入后假定未执行 | 正在执行的调用不会立即暂停 |
| FastAPI/Pydantic/Uvicorn + HTTPX | 由成熟组件处理通用 HTTP、请求校验与异步传输 | Web 异步不等于工具可强制中止，调用生命周期仍要自己管理 |
| 原生 JavaScript 模块与 SSE | 让界面消费真实事件，配置与状态逻辑可单独测试 | 没有前端框架；后续是否迁移取决于维护成本 |
| Tool 为共同入口 | 函数助手、文件插件与 MCP 共用执行器 | 适配器是可信宿主代码；不是插件沙箱 |
| 字符预算与完整轮次裁剪 | 低成本保护当前工具配对与输入，不依赖供应商 tokenizer | 不能精确预测 token 或费用，超限时可能直接失败 |
| 词法检索默认离线，Embedding 显式可选 | 无密钥也能走通有来源的检索；需要时可接真实向量服务 | 词法不能理解同义改写；向量质量需要独立验证 |
| 模型、目录、工具、Skill 按运行绑定 | 页面切换或配置编辑不改变已有审批与恢复目标 | 某些升级或配置变化要求结束旧任务、重建索引或重启加载 |
| 确定性评分、故障注入与分开报告 | 核对执行行为、产物与恢复安全，而不只看回答文字 | 离线固定模型成绩不能代表真实 LLM 能力 |
| 锁定依赖、源码包和安装包验证 | 让新环境能安装到明确的一组运行组件 | 锁文件、资源清单与使用教程需要一起维护 |

## 执行可靠性：安全停止也是结果

检查点可以记录“上一步已保存”，但无法把外部工具与本地 SQLite 合并成一个事务。副作用已发生、结果未落盘时，重新执行可能比停止更危险。因此 `unknown` 保留调用与诊断，阻断继续；人工核查只解除阻断，不改写原运行结果。

暂停采用另一条语义：保存请求，等待当前调用收尾，在下一个调用前停住。取消则尽力终止等待；不能强杀的同步处理函数或远端服务仍可能继续执行。这些区别直接影响 UI 文案、实验完成率与恢复图，详见 [持久化与恢复](ARCHITECTURE.md#持久化与恢复)。

命令工具使用显式程序白名单、argv、最小环境与自有进程树清理，没有引入任意 shell 展开。代价是使用者需要明确选程序；获准程序仍有宿主账号的文件和网络能力，不能把 cwd 检查称为 OS 沙箱。

## 工具与协议：统一执行，分开生命周期

`tool_from_function` 把受信任函数转换为 Tool，降低维护 Schema 的重复工作；它不承担执行、权限或隔离。文件编辑、检索和 MCP 发现结果也沿相同注册入口接入，Engine 不按来源分支。

连接管理留在适配层：MCP manager 持有进程或 HTTP 客户端，Registry 只保存工具定义。每个服务独立命名空间和状态，动态配置在受控边界更新；重启不自动启动用户登记的服务。这样减少普通工具定义与进程生命周期之间的耦合。

当前 MCP 客户端实现明确的工具子集。既有阶段评估过官方 [Python SDK v1 文档](https://py.sdk.modelcontextprotocol.io/v1/)，当时立即迁移还需适配会话循环与原始响应限额，没有减少总改动；这不是永久坚持手写协议的原则。若后续需要远程认证、订阅或更多协议能力，应重新比较 SDK 与自行维护的成本，而非直接放宽现有限制。

## 上下文与检索：控制返回量，再讨论检索质量

文件片段工具独立于 `files.read`，保留旧参数和字符串返回。行列游标支持长单行，固定返回量控制模型输入；整文件大小、编码与路径仍完整检查。它优化的是进入上下文的内容量，不承诺减少磁盘扫描或总耗时。

默认索引使用 SQLite [FTS5](https://sqlite.org/fts5.html)，材料与元数据可以在同一事务内更新。trigram 提供字面候选，短词使用有界扫描；每次查询重新核对来源。因此它容易在本机复现，但不能替代语义检索，候选上限也可能漏掉后面的片段。

可选 Embedding 复用 HTTPX 与 SQLite 向量存储，不要求大型下载或新数据库进程。配置、语料和维度变化要显式重建，服务失败不静默改用词法结果。测试、重建和查询都会外传文本并可能计费，统一纳入工具审批；离线手工向量只验证协议和排序流程。

## 配置与指导：对新任务生效，旧任务可追溯

工作区输入采用真实后端路径，不引入目录上传或自动全盘发现。模型档案只保存非秘密配置与环境变量引用，选择影响新任务；已有会话不能暗中换模型。MCP 保存意图与活动连接分开，Embedding 保存后通过重启加载，减少运行期间替换对象的分支。

Skill 采用固定目录下的小型文本格式，按需读取并为单次任务冻结正文。它是任务指导数据，不是新执行层，不运行附带脚本，不授予工具权限，也不宣称兼容所有外部 Skill 格式。用户可以用文本编辑器添加指导，而无需写 Python。

这些选择优先保证审批对象和恢复对象清楚。代价是配置热更新能力有限，操作步骤有显式确认；具体支持范围分别见 [工作区](WORKSPACES.md)、[模型档案](MODEL_PROFILES.md)、[MCP 档案](MCP_PROFILES.md)、[Skill](SKILLS.md)。

## 评测：先确保比较条件成立

工具身份同时使用显式版本、函数 AST 和声明的辅助函数／常量，避免仅比较 Schema 漏掉实现变化，也避免只用手写版本号漏掉未更新版本的改动。说明文字单独记录，减少文案变化导致的不必要拒绝。没有递归推导任意依赖图，也不把摘要当作供应链证明。

故障实验核对真实临时文件和调用记录。任务级实验把“状态完成”“产物正确”“两者同时成立”分开，保留 unknown 与失败。简单重跑和检查点继续同时改变运行身份、位置与预算，属于策略对照，不是只改变一个开关的因果消融。注入的时钟偏移不用于宣称真实耗时改善。

已有真实模型记录只支持报告中明确列出的模型、传输路径和任务。之后更换适配器、工具集合或提示，不能直接沿用旧成绩；新的外部测试需另行明确数据、费用和范围。协议与结果见 [评测文档](EVALUATION.md)。

## 什么时候需要重新选择

出现可复现的维护或性能问题，再决定是否引入前端框架、完整 MCP SDK、更精确的上下文预算或新的调度方式。记录应包含触发问题、备选方案、兼容影响与验收方法；未实施方案只放在 [路线图](ROADMAP.md)，不为未来能力先建空模块。
