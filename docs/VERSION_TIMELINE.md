## 应该下载哪一份

- **希望稳定复现：** 从 [Release 页面](https://github.com/ytinyx/astra-harness/releases/tag/v0.5.0) 下载 Source code，或检出 `v0.5.0`。
- **希望参与开发：** 使用 `main` 分支，记录实际提交 SHA；它可能包含下一个版本的修改。
- **需要 Python 安装包：** 按 [打包指南](PACKAGING.md) 从选定源码构建。GitHub 自动源码归档不等于 wheel 或 Python sdist；本项目尚未在 PyPI 分发。

包版本说明发行范围，提交 SHA 标识精确源码，CI 结果证明该提交在所列环境执行过哪些检查。这三者不能互相替代。

## 升级前检查

1. 先处理待审批任务和 `unknown` 结果，关闭使用同一数据库的服务进程。
2. 备份本地数据库、工作区和个人配置；不要提交密钥或私人材料。
3. 阅读目标版本的兼容说明。工具、模型、目录或 Skill 身份改变时，旧任务可能无法继续。
4. 安装目标版本，运行 `doctor` 和离线示例，再启用自己的模型与外部服务。

升级不会自动重放旧工具调用，也不保证所有开发阶段的数据库和任务都能迁移。身份不匹配时，应核查旧任务并新建任务，不应手改数据库绕过检查。

## 版本规则

- 公开版本采用 `MAJOR.MINOR.PATCH`，Git 标签为 `vMAJOR.MINOR.PATCH`；已发布标签不移动、不复用。
- `0.x` 阶段仍可能调整接口和状态格式。兼容修正使用补丁版本，新增能力或不兼容变化在后续次版本中明确说明。
- 只有实际准备下个版本的修改时，变更日志才使用“未发布”章节；它不表示现有正式版本尚未公开。
- 路线图记录方向，不提前创建版本、标签或验收结果。

## 早期开发记录

公开仓库从当前源码建立历史。早期本地记录中的 `0.2.0`、`0.3.0` 和 `Sxx` 阶段编号不是本仓库的公开发行，不列入 Release 清单；内部阶段顺序也不作为历史测试时间的证明。原始记录保留，公开版本从 `v0.4.0` 开始。
