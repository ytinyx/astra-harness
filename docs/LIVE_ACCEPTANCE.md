# 真实模型验收准备

[项目首页](../README.md) · [文档地图](README.md) · [验证状态](../HANDOFF.md)

这份协议用于准备一次新的真实模型验收，不附历史成绩、费用账本或私人执行脚本。阅读文档、保存模型配置和运行 `doctor` 都不等于授权付费请求。默认新手路线继续使用离线模型。

## 先确定验收条件

1. 明确服务、实际端点、模型标识及支持的协议；通过使用者主动配置的环境变量提供密钥，不把凭据写入文档或报告。
2. 固定源码、工具身份、任务输入、评分预期、上下文与输出限制。模型只获得任务材料和必要工具信息，不读取评分答案。
3. 明确本轮费用上限、请求数、单次超时和累计执行预算；记录价格与模型限制的官方依据。没有可证明的金额约束时，不把估算费用称为硬上限。
4. 先用可信本地替身验证参数、取消、预算停止和产物评分，再决定是否开始真实请求。

配置方法见 [模型档案](MODEL_PROFILES.md)。模型档案的“测试连接”本身会发送一条合成请求，并可能计费；保存配置不会自动测试。

## 最小任务路线

每个任务使用独立运行记录。材料只来自新建隔离工作区中的三份内置虚构会议记录，不发送项目源码、个人文件或完整历史对话。

| 顺序 | 任务 | 独立判据 | 准备重点 |
| --- | --- | --- | --- |
| 1 | 简短对话 | 正常完成且实际工具调用为 0 | 验证传输与结束标记，不先执行写入 |
| 2 | 计算 -8 + 3 | 实际 add 结果为 -5，回答与之相符 | 不能只凭最终文本评分 |
| 3 | 搜索“取消”并读取命中行 | 路径、行号、原文及结构字段与合成输入一致 | 明确所需 JSON 字段与输出契约 |
| 4 | 读取会议材料并写 todos.json | 审批前无文件；批准后完整内容符合独立预期 | 核对调用身份和参数，只批准所需写入 |

先跑前两项确认基本链路，再决定是否继续较长任务。可通过单案例 benchmark 复用 [任务集与产物评分](EVALUATION.md#评分必须观察真实效果)，但应明确任务是否适合该模型与当前提示。预期产物必须独立定义，不能让模型自行评价成功。

次数、输出 token、上下文、单次与整轮时间限制由本次批准范围确定，不沿用过去轮次的额度。`forbidden_tools` 是评测后的评分条件，不能代替执行权限；写入要使用审批停止模式，禁止循环自动批准作为验收捷径。

## 费用与请求准入

**当前发布源码没有账户级金额封顶，也没有通用的货币预算门禁。** 运行配置提供次数、时间和字符预算；这些约束有助于限制工作量，但不能单独保证费用不超过某个金额。

若验收必须具有本地金额约束，需要在请求前可靠预留最坏费用，并把全部重试、失败及不确定请求计入同一账本。只有在服务的价格、上下文与输出限制均明确适用时，才可据此计算保守上界：

```text
单次预留 = 保守输入 token 上界 × 输入单价
         + 强制输出 token 上限 × 输出单价
         + 本次请求可能包含的其他收费项

准入条件 = 已结算费用 + 未决预留 + 单次预留 ≤ 本轮授权金额
```

价格的单位必须统一。近似 tokenizer、字符数、调用次数或超时都不能代替输入上界；上下文限制的定义及输出是否占用上下文要按实际服务核实。无法证明上界、存在未纳入收费的能力或账本状态不明时，应停止该轮准备，而不是发送请求后再估算。

完整最终 usage 返回并经校验后，才能按相同价格口径结算和释放差额；没有完整用量就保留预留。供应商账单与根据 usage 计算的费用是两种证据，报告必须区分。本地控制也不能限制同一账户中其他程序的请求。

## 运行与停止规则

- 禁止隐式重试；若执行路径确实可能重试，每次请求必须重新准入并计入总预算。
- 固定端点与参数，拒绝意外重定向，不把凭据或任务材料发给另一服务。
- 校验响应完整性、结束状态和用量字段。早期流片段不等于最终结算证据。
- 超时、取消、断连或结果不明时停止继续请求；本地等待结束不证明远端已经停止计费或执行。
- 认证失败不盲目重复调用；写操作结果不明时保持 unknown，不以重发工具来“确认”。
- 评分失败保留原任务及报告。修正提示或配置后创建独立复测，仍计入本轮剩余预算，不能把原失败改成通过。

审批、恢复和工具身份仍由正式运行时校验。重开 Application 或更换模型配置不得让旧调用沿用不匹配的批准；配置变化应明确停止或另建任务。

## 保存可核查的结果

每次验收记录以下内容，结果仍以实际执行为准：

| 证据 | 用途 |
| --- | --- |
| 模型、端点、参数和价格依据 | 说明结果适用于哪个服务与配置 |
| 源码、输入、工具身份与完整预算 | 支持复现和条件比较 |
| 调用、审批、状态、产物与独立评分 | 区分回答正确、实际工具效果和执行完成 |
| 最终 usage、结算口径与未决费用 | 区分已知消耗、保守预留和供应商实付 |
| 实际执行时间、失败和单独复测 | 防止把新测试写成过去阶段的结果 |

原始记录保存在使用者本机。对外分享前采用明确字段白名单，排除密钥、请求头、账户明细、私人路径和无关材料；不只选择成功案例。少量真实模型任务只能支持相应配置下的有限观测，不能推出泛化成功率或后续所有适配器已经验收。
